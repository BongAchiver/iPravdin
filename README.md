# iPravdin для Firefox

Адаптация [vint352/iNikolayev-v.2](https://github.com/vint352/iNikolayev-v.2), основанного на расширении drugoi/iNikolayev. Версия 2.0.1 заменяет изображения на страницах двумя локальными фотографиями Правдина, предоставленными пользователем. Требуется Firefox 140+ на компьютере. Манифест также задаёт минимум Firefox 142 для Android; Android отдельно не тестировался.

## Установка

1. Откройте Firefox и перейдите на `about:debugging#/runtime/this-firefox`.
2. Нажмите **«Загрузить временное дополнение…»**.
3. Выберите `app\manifest.json` или `dist\ipravdin-firefox-2.0.1.xpi`.
4. Обновите ранее открытые веб-страницы. При необходимости разрешите расширению доступ к сайтам в `about:addons`.
5. Откройте значок iPravdin на панели инструментов. Кнопка **«Все настройки»** открывает полную страницу настроек.

Временное дополнение удаляется после перезапуска Firefox. XPI в `dist` **не подписан**: для постоянной установки в обычном Firefox нужно получить подпись Mozilla.

### Постоянная установка без публикации в каталоге

1. Выполните `npm run build`.
2. Войдите в [Mozilla Add-ons Developer Hub](https://addons.mozilla.org/developers/) с Mozilla Account и начните отправку нового дополнения.
3. Выберите **On your own** (самостоятельное распространение), чтобы расширение не появилось в публичном каталоге.
4. Загрузите `dist/ipravdin-firefox-2.0.1.zip`, пройдите проверку и скачайте **подписанный** XPI после получения подписи.
5. В Firefox откройте `about:addons`, нажмите шестерёнку → **Установить дополнение из файла…** и выберите подписанный XPI. Такая установка сохраняется после перезапуска браузера.

Этот режим не привязывает файл к одному пользователю: другой человек с копией XPI тоже сможет его установить. Автообновление настроено через GitHub Releases репозитория BongAchiver/iPravdin. Исходники и опубликованные сборки в этом публичном репозитории доступны другим пользователям; персональные данные my.itmo в репозиторий не входят.

### Выпуск обновлений из GitHub без ручной загрузки в Dev Hub

1. Один раз получите [API-ключи Mozilla](https://addons.mozilla.org/developers/addon/api/key/): JWT issuer и JWT secret.
2. В репозитории `BongAchiver/iPravdin` откройте **Settings → Secrets and variables → Actions**. Добавьте два repository secrets: `AMO_JWT_ISSUER` и `AMO_JWT_SECRET`.
3. Сохраните изменения кода в Git и отправьте их в GitHub.
4. Откройте **Actions → Sign and release iPravdin → Run workflow**, выберите ветку и задайте новую версию, например `2.0.2`. Версия должна быть выше ранее выпущенной. Один номер версии нельзя подписывать повторно.
5. Workflow проверит проект, отправит расширение на подпись через API Mozilla в канале `unlisted` и создаст GitHub Release с файлами `ipravdin.xpi` и `updates.json`.
6. Первый подписанный `ipravdin.xpi` установите из файла через `about:addons`. Firefox будет проверять `https://github.com/BongAchiver/iPravdin/releases/latest/download/updates.json` и скачивать подписанные обновления. Проверку можно запустить вручную из меню шестерёнки в `about:addons`.

Workflow устанавливает указанную версию в файлы сборки, но не коммитит её обратно в исходники. При необходимости обновить версию локально выполните `npm run version:set -- 2.0.2`. Тег релиза указывает на использованный коммит исходников; готовый XPI содержит версию из поля запуска workflow.

Каждая версия всё равно проходит подпись Mozilla: автоматизация заменяет загрузку через веб-интерфейс. Проверка или ручное рассмотрение Mozilla могут задержать выпуск. GitHub не подписывает расширения самостоятельно. Если репозиторий станет приватным, эта схема доставки перестанет работать без отдельного доступного по HTTPS хостинга.

Для подписи с компьютера используйте переменные окружения `WEB_EXT_API_KEY` и `WEB_EXT_API_SECRET`, затем `npm run sign`. Сборки скачиваются в `dist/signed`; для каждого выпуска используйте свежую папку. `npm run updates:prepare -- https://github.com/BongAchiver/iPravdin/releases/download/v2.0.2/ipravdin.xpi` создаёт файл обновлений и копию скачанного XPI в `dist/release`. Эта команда предназначена для результата `web-ext sign`, она не проверяет криптографическую подпись самостоятельно.

Официальные инструкции: [подпись через web-ext](https://extensionworkshop.com/documentation/develop/web-ext-command-reference/#web-ext-sign), [обновления по HTTPS](https://extensionworkshop.com/documentation/manage/updating-your-extension/).

Технический ID `inikolayev-firefox@vint352.local` сохранён для совместимости с ранее установленной версией и её настройками; название, пути к ресурсам и имя сборки используют iPravdin.

Официальные инструкции: [временная установка](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/), [самостоятельное распространение](https://extensionworkshop.com/documentation/publish/self-distribution/).

## Возможности

- Полная страница настроек и всплывающее окно; автоматическая светлая и тёмная темы, клавиатурное управление и подписи элементов.
- Включение и выключение без перезагрузки: исходные адреса, `srcset`, `sizes` и изменённые расширением свойства стилей восстанавливаются.
- Динамически добавляемые картинки, ленивая загрузка через изменение `src`/`srcset`, элементы `<picture>` и HTTP/HTTPS iframe.
- Исключения для доменов и их поддоменов; международные домены преобразуются в punycode.
- Защита небольших иконок: изображения с шириной или высотой меньше 48 px по умолчанию остаются исходными.
- Настраиваемое контекстное меню с реальным включением/выключением; отметка OFF на значке при отключении.
- Две локальные фотографии Правдина, включая 3 сентября. Снимки Николаева и Шуфутинского удалены из новой сборки.
- Если сайт блокирует подменённую картинку, расширение возвращает оригинал вместо бесконечных повторных попыток.

Изображения обрабатываются по изменениям DOM, без постоянного опроса страницы. Настройки и список исключений хранятся только в `storage.local`, без синхронизации аккаунта. Расширение не отправляет сетевых запросов на сторонние серверы, не загружает внешний код и не содержит аналитики.

## Ограничения

### Расписание my.itmo: план подключения

Получение расписания пока не реализовано. В публичных JavaScript-файлах my.itmo обнаружен запрос `GET /api/schedule/schedule/personal` с параметрами `date_start`, `date_end` (`YYYY-MM-DD`) и необязательным `subject_id`. Виджет использует ответ `data.data` как список дней с `lessons`; карточка занятия читает `time_start`, `time_end`, `subject`, `teacher_name`, `room` и `building`. Клиент сайта использует Bearer-токен через Nuxt Auth. Поэтому нельзя предполагать, что запрос с одними cookies будет авторизован.

Для подключения нужно проверить этот запрос в пользовательской авторизованной вкладке. Скрипт расширения на my.itmo сможет использовать действующую сессию, не запрашивая пароль; токен нельзя сохранять в Git или передавать на GitHub/Mozilla. Проверка проводилась только по публичному коду сайта, без доступа к персональному расписанию пользователя.

В интерфейсе можно показывать день и неделю, начало и конец пары, предмет, преподавателя, аудиторию, ближайшую пару и время последнего обновления. Локальный кэш нужно явно отмечать как сохранённые данные, а истёкшую сессию — как необходимость снова войти на my.itmo. Текущая политика `connect-src 'none'` запрещает сетевые запросы из страниц расширения; при подключении API её нужно будет изменить для проверенных адресов ИТМО.

### Замена изображений

Расширение работает с HTML-элементами `<img>`. CSS-фоны, canvas, изображения в shadow DOM и встроенный просмотрщик PDF не заменяются. Внутренние страницы Firefox, Mozilla Add-ons и другие защищённые страницы недоступны расширениям. Не изменяйте системные ограничения ради замены изображений.

После удаления или временной выгрузки расширения обновите страницу, если на ней остались подменённые изображения. Выключение штатным переключателем восстанавливает их сразу. Страницы, которые непрерывно перезаписывают DOM, могут конфликтовать с подменой: добавьте такой домен в исключения.

## Разработка и проверки

Node.js 22.21+ и npm. Selenium Manager при первом запуске браузерных тестов может скачать geckodriver; для этого нужен интернет. Тест использует отдельный временный профиль и не изменяет личный профиль Firefox.

```powershell
cd E:\iNikolaev
npm ci
npm test
npm run lint
npm audit
npm run build
npm run test:firefox
```

`npm run lint` использует официальный Mozilla Add-ons Linter с предупреждениями как ошибками. `npm run build` создаёт ZIP и неподписанный XPI, содержащие только `app`. Для Firefox на другой ОС измените путь к бинарному файлу в `tests/firefox.cjs`.

`web-ext` — инструмент разработки и подписи, он не включается в XPI. На момент настройки `npm audit` сообщает об уязвимости `node-forge` в его зависимости для Android (`@devicefarmer/adbkit`) и отмечает три связанных пакета с уровнем high. Исправленная версия `node-forge` пока недоступна в npm; автоматический downgrade web-ext до 5.x не применяется. Перед использованием Android-инструментов следует обновить зависимости после выхода исправления.

Проверено 2 октября 2026 года: 12 тестов логики и подготовки выпуска; браузерный сценарий в Firefox 157.0 на Windows; Mozilla Linter в режиме самостоятельного распространения — 0 ошибок, 0 предупреждений. Состояние npm audit после добавления web-ext описано выше и в SECURITY.md. Браузерные снимки доступны после теста в `artifacts/settings-light.png`, `artifacts/settings-dark.png`, `artifacts/popup.png`. Подпись Mozilla и автоматическая установка обновления ещё не проверены: для этого нужны API-ключи и первый подписанный выпуск.

Структура: `app/manifest.json` — Firefox MV3; `app/ipravdin/bg.js` — фоновая событийная страница; `settings.js` — настройки и проверка доменов; `ipravdin.js` — замена и восстановление; `options/` — интерфейс; `photos/` — локальные ресурсы и сведения об авторах.
